== 📖 Présentation du Projet

Bienvenue sur le prototype (Proof of Concept) du portail de réservation pour le **Synchrotron SOLEIL**. 
Ce projet a été développé intégralement de zéro suite à notre récent échange, afin de démontrer techniquement la faisabilité des besoins exprimés pour ce poste.

Il s'agit d'une plateforme complète permettant aux chercheurs de consulter les disponibilités des experts et des lignes de lumière, et de gérer leurs réservations.

**Fonctionnalités clés implémentées :**
* 🧠 **Assistant IA (Gemini 2.5 Flash)** : Un moteur de recherche en langage naturel permettant de filtrer dynamiquement les experts (ex: *"Je cherche un spécialiste en cristallographie"*).
* 📅 **Recherche Multicritères Avancée** : Filtres simultanés stricts (menus déroulants), flous (recherche par nom ou discipline tolérant les fautes d'orthographe via l'algorithme de Levenshtein) et temporels (sélecteurs natifs de Date et Heure).
* 🔐 **Authentification Hybride & Sécurisée** : Connexion classique par e-mail avec validation SMTP, et OAuth 2.0 (Google, GitHub, LinkedIn). Sessions gérées via des cookies `HttpOnly`.
* 👤 **Gestion de Profil & Conformité RGPD** : Espace utilisateur interactif pour la mise à jour des informations personnelles, le changement sécurisé de mot de passe, et l'exercice du droit à l'oubli (suppression définitive et automatisée du compte).
* 📧 **Notifications & Tâches Planifiées (Celery/Redis)** : Envoi d'e-mails transactionnels immédiats (création, annulation) et asynchrones en arrière-plan, comme l'envoi automatique d'un rappel aux patients la veille de leur rendez-vous à 08h00.
* 🧪 **Fiabilité** : Logique métier couverte par des tests automatisés ciblant les règles de gestion (Jest pour le front-end, Pytest pour le back-end).

== 🏗️ Architecture et Composants

L'application repose sur une architecture moderne, modulaire et entièrement conteneurisée avec Docker :

* 🎸 link:./backend/README.adoc[**backend (Django)**] : Le serveur API REST principal (Port 8000). Gère la base de données PostgreSQL, la logique de réservation, le pont avec l'IA Google Gemini, et orchestre les *workers* asynchrones Celery.
* ⚛️ link:./frontend/README.adoc[**frontend (React)**] : L'interface utilisateur interactive et réactive développée avec Vite et TypeScript (Port 5173).
* 🐳 **docker-compose.yml** : L'orchestrateur central qui connecte le front-end, le back-end, la base de données PostgreSQL et le broker Redis dans un réseau virtuel isolé.

== 🛠️ Prérequis

Pour exécuter ce projet sur votre machine, vous avez uniquement besoin de :
* **Docker** et **Docker Compose** installés.
* Configurer **deux fichiers `.env`** (un à la racine, un dans le front-end) détaillés dans la section suivante.

== ⚙️ Configuration des variables d'environnement (.env)

Pour faire fonctionner l'ensemble de l'architecture, vous devez créer deux fichiers distincts.

=== 1. Le fichier `.env` à la racine (Back-end, BDD & Celery)
Créez un fichier nommé `.env` à la racine absolue du projet (au même niveau que le `docker-compose.yml`) :

[source,properties]
----
# --- CONFIGURATION DJANGO ---
SECRET_KEY=votre_cle_secrete_django_tres_longue
ALLOWED_HOSTS=localhost,127.0.0.1,backend

# --- BASE DE DONNÉES POSTGRESQL ---
POSTGRES_DB=synchrotron_db
POSTGRES_USER=postgres
POSTGRES_PASSWORD=votre_mot_de_passe_db
POSTGRES_HOST=db
POSTGRES_PORT=5432

# --- URL FRONTEND ---
FRONTEND_URL=http://localhost:5173

# --- GOOGLE GEMINI IA ---
GEMINI_API_KEY=votre_cle_api_google_ai_studio

# --- EMAIL SMTP (Ex: Gmail) ---
EMAIL_HOST_USER=votre_email@gmail.com
EMAIL_HOST_PASSWORD=votre_mot_de_passe_application_de_16_lettres
----

=== 2. Le fichier `.env` dans le dossier Front-end (React)
Créez un second fichier nommé `.env` directement **à l'intérieur du dossier `frontend/`** :

[source,properties]
----
# --- AUTHENTIFICATION OAUTH 2.0 (Interface) ---
VITE_GOOGLE_CLIENT_ID=votre_client_id_google
VITE_GITHUB_CLIENT_ID=votre_client_id_github
----

== 🔑 Tutoriel : Obtenir vos Clés et Configurer les Services externes

=== 1. Obtenir la clé Google Gemini (Pour l'Assistant IA)
1. Allez sur https://aistudio.google.com/[Google AI Studio].
2. Connectez-vous avec un compte Google.
3. Cliquez sur **"Get API key"** à gauche, puis sur le bouton bleu **"Create API key"**.
4. Copiez cette clé et collez-la dans la variable `GEMINI_API_KEY` de votre fichier `.env` à la racine.

=== 2. Configurer la connexion avec GitHub et Google (OAuth 2.0)

==== 🌐 Google Cloud Console
1. Allez sur la link:https://console.cloud.google.com/[Google Cloud Console].
2. Créez un nouveau projet.
3. Accédez à **API et services > Identifiants**.
4. Cliquez sur **Créer des identifiants > ID de client OAuth**.
5. Configurez l'écran de consentement en mode **"Externe"**.
6. **Origines JavaScript autorisées :** Ajoutez `http://localhost:5173`
7. **URI de redirection autorisés :** Ajoutez `http://localhost:5173/auth/google/callback`
8. Notez votre **Client ID** et copiez-le dans la variable `VITE_GOOGLE_CLIENT_ID` de votre fichier `frontend/.env`.

==== 🐙 GitHub Developer Settings
1. Allez dans vos **Settings** GitHub > **Developer Settings** > **OAuth Apps**.
2. Cliquez sur **New OAuth App**.
3. **Homepage URL :** `http://localhost:5173`
4. **Authorization callback URL :** `http://localhost:5173/auth/github/callback`
5. Cliquez sur **Register application**.
6. Copiez le **Client ID** généré et mettez-le dans la variable `VITE_GITHUB_CLIENT_ID` de votre fichier `frontend/.env`.

=== 3. Obtenir le mot de passe d'application Google (Pour l'envoi d'e-mails SMTP)
Pour des raisons de sécurité, Google n'autorise plus la connexion avec votre mot de passe habituel pour les envois automatisés.
1. Allez sur les https://myaccount.google.com/security[Paramètres de sécurité de votre compte Google].
2. Activez la **Validation en deux étapes** si ce n'est pas déjà fait.
3. Cherchez **"Mots de passe des applications"** dans la barre de recherche des paramètres.
4. Générez un mot de passe (donnez-lui le nom "Synchrotron").
5. Google va afficher un code de 16 lettres. **Copiez-le sans les espaces** et collez-le dans votre variable `EMAIL_HOST_PASSWORD` à la racine.

== 🚀 Lancement Global de l'Application

La manière la plus simple de lancer toute l'architecture d'un seul coup est d'utiliser Docker Compose.

. Ouvrez un terminal à la racine du projet.
. Tapez la commande suivante pour construire et lancer les conteneurs :
+
[source,bash]
----
docker compose up --build
----
. Patientez quelques secondes le temps que la base de données s'initialise et que les serveurs démarrent.
. Le portail est prêt !
* ⚛️ **Accédez à l'Interface Utilisateur (React) :** `http://localhost:5173`
* 🎸 **Accédez à l'API (Django) :** `http://localhost:8000/api`

== 🧪 Tester les envois d'e-mails asynchrones (Celery)
L'application intègre un "CRON" automatisé qui envoie chaque matin à 08h00 un e-mail de rappel aux patients ayant un rendez-vous le lendemain. 
Pour vérifier ce fonctionnement en environnement de développement, vous avez deux options :

**Méthode 1 : Simulation Naturelle**
1. Sur le portail React, réservez un créneau daté d'exactement **demain** (peu importe l'heure).
2. Laissez tourner les conteneurs et patientez jusqu'au lendemain matin 08h00. Vous recevrez l'e-mail automatique.

**Méthode 2 : Déclenchement Forcé (Terminal)**
Si vous ne souhaitez pas attendre demain matin à 08h00 :
1. Sur le portail React, réservez un créneau daté d'exactement **demain**.
2. Ouvrez un terminal et forcez l'exécution immédiate de la tâche en arrière-plan avec cette commande :
+
[source,bash]
----
docker compose exec backend python manage.py shell -c "from booking.tasks import envoyer_rappels_rdv; resultat = envoyer_rappels_rdv(); print('\n=== RÉSULTAT DE LA TÂCHE ===\n' + resultat + '\n============================\n')"
----
3. Le terminal confirmera l'envoi et vous recevrez l'e-mail de rappel instantanément.

== 🛑 Comment arrêter le projet ?

Pour stopper proprement tous les services (Serveurs, Base de données, Redis, Workers) et libérer les ports de votre machine, appuyez sur `Ctrl + C` dans le terminal qui exécute Docker, puis tapez :

[source,bash]
----
docker compose down
----

_Astuce : Si vous souhaitez réinitialiser entièrement la base de données (supprimer tous les utilisateurs et réservations test), ajoutez l'argument `-v` (`docker compose down -v`)._
